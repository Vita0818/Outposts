## DeepCode 输出文件字段

每个 DeepCode one-shot 必须将结构化报告写入 supervisor 指定的 `DeepCode-output/<BATCH_NAME>/*.md`。

必填字段：

```text
WORKER: DeepCode_ONE_SHOT
MODEL_CHECK_RESULT:
PATH_CHECK_RESULT:
PROJECT_NAME:
PROJECT_PATH:
BATCH_NAME:
ROUND_ID:
OUTPUT_FILE_WRITTEN:
TASK_RECEIVED:
PREVIOUS_DEEPCODE_REPORTS_READ:
QWENCODE_REPORTS_REQUESTED_BY_SUPERVISOR:
QWENCODE_REPORTS_READ:
QWENCODE_FINDINGS_USED:
QWENCODE_REPORT_READ_FAILURES:
FILES_READ_SUMMARY:
FILES_CHANGED:
COMMANDS_RUN:
BUILD_RESULT:
TEST_RESULT:
ACTUAL_SCREENSHOTS_GENERATED:
USER_FEEDBACK_ADDRESSED:
IMPLEMENTED_THIS_ROUND:
REMAINING_UI_DIFFERENCES:
REMAINING_FUNCTIONAL_GAPS:
BLOCKERS:
REGRESSION_RISKS:
NEXT_RECOMMENDATION:
READY_FOR_USER_REVIEW:
REPORT_COMPLETE:
```

`FILES_READ_SUMMARY` 只能摘要范围，不要求贴源码。`COMMANDS_RUN` 应列命令和结果摘要。`BUILD_RESULT`、`TEST_RESULT` 必须区分未运行、无法运行、失败、通过。

当 DeepCode 根据 QwenCode 报告修正时，还必须包含：

```text
QWENCODE_REPORTS_USED_FOR_THIS_ROUND:
QWENCODE_VISUAL_FINDINGS_APPLIED:
CODE_CHANGES_FROM_QWENCODE_REPORT:
VISUAL_GAPS_REMAINING_AFTER_FIX:
```

如果读取 QwenCode 报告失败：

```text
QWENCODE_REPORT_READ_FAILURES:
DID_NOT_USE_QWENCODE_RESULT=YES
```

不得声称已根据 Qwen 视觉结果修复。

## QwenCode 输出文件字段

每个 QwenCode one-shot 必须将结构化视觉报告写入 supervisor 指定的 `QwenCode-output/<BATCH_NAME>/*.md`。

必填字段：

```text
WORKER: QwenCode_ONE_SHOT
MODEL_CHECK_RESULT:
PATH_CHECK_RESULT:
MODEL: Qwen3.7-Plus
PROJECT_NAME:
PROJECT_PATH:
BATCH_NAME:
ROUND_ID:
OUTPUT_FILE_WRITTEN:
VISUAL_TASK_TYPE:
REFERENCE_SCREENSHOT_READ:
ACTUAL_SCREENSHOT_READ:
QWENCODE_CALLED:
QWENCODE_VALID_VISUAL_EVIDENCE:
QWENCODE_COMPARE_COMPLETED:
SCREENSHOT_VALIDITY_NOTES:
PAGE_STRUCTURE_SUMMARY:
VISIBLE_TEXT_SUMMARY:
COLOR_LAYOUT_FONT_SUMMARY:
MAJOR_VISUAL_DIFFERENCES:
FIX_RECOMMENDATIONS:
REMAINING_VISUAL_BLOCKERS:
VISUAL_VALIDATION_LIMITATIONS:
REPORT_COMPLETE:
```

`QWENCODE_CALLED=YES` 不等于有效验收。无效桌面截图必须报告 `QWENCODE_VALID_VISUAL_EVIDENCE=NO`。reference-only 必须明确写 `QWENCODE_VALID_VISUAL_EVIDENCE=REFERENCE_ONLY`。

## Android screenshot preflight 报告字段

DeepCode 如执行 Android screenshot preflight，必须报告：

```text
ANDROID_EMULATOR_LOCK:
ANDROID_ADB_PATH:
ANDROID_ADB_STATUS:
ANDROID_DEVICE_SERIALS:
APPLICATION_ID_SOURCE:
APPLICATION_ID:
PACKAGE_INSTALLED_BEFORE_PREFLIGHT:
INSTALL_NEEDED_FOR_SCREENSHOT:
INSTALL_COMMAND:
INSTALL_RESULT:
APP_LAUNCH_COMMAND:
FOREGROUND_PACKAGE_CHECK:
FOREGROUND_PACKAGE:
FOREGROUND_PACKAGE_RETRY_COUNT:
ACTUAL_SCREENSHOT_PATH:
SCREENSHOT_CHAIN_STATUS:
INVALID_SCREENSHOTS:
```

字段规则：

- `INSTALL_NEEDED_FOR_SCREENSHOT=YES` 表示为了截图链在当前项目内执行了最小安装流程，不等于普通功能开发。
- `INSTALL_FOR_SCREENSHOT_FAILED` 时不得继续 UI 修改。
- `FOREGROUND_PACKAGE` 必须等于目标 `APPLICATION_ID` 后，`ACTUAL_SCREENSHOT_PATH` 才能计为有效 actual screenshot。
- 截到另一个项目 App 时，必须列入 `INVALID_SCREENSHOTS`，不得作为 QwenCode 有效验收或 compare 依据。

## Codex 主管摘要字段

Supervisor 给用户的摘要应包含：

```text
BATCH_NAME
MODE
INITIATOR
SUPERVISOR
MODEL_CHECK_RESULT
PATH_CHECK_RESULT
SCOPE_CONFIRMATION
PROJECT_STATUS_SUMMARY
DEEPCODE_OUTPUTS
QWENCODE_OUTPUTS
BUDGET_STATUS
BLOCKERS
USER_FEEDBACK_STATUS
NEXT_RECOMMENDED_ACTION
UNCERTAINTIES
```

用户只需要看主管摘要。不得把 DeepCode / QwenCode 长报告整段贴给用户。必要时只摘取关键结论、阻塞、验证结果和下一步。

当目标涉及 UI 复刻时，主管摘要应简要保留：是否使用 QwenCode、是否有参考图、是否有实际渲染图、主要视觉差异、是否已根据视觉差异修正、剩余视觉验收阻塞。

每个项目摘要建议使用：

```text

LATEST_QWENCODE_REPORT_PATH
LATEST_ACTUAL_SCREENSHOT_PATH
BUILD_RESULT
TEST_RESULT
BLOCKER
NEXT_ACTION
```

## 预算字段

预算摘要必须包含：

```text
BATCH_TIME_BUDGET_MINUTES
TIME_BUDGET_REACHED
MAX_REPORT_ROUNDS_PER_PROJECT
ROUNDS_COMPLETED_BY_PROJECT
VISION_ROUNDS_COMPLETED_BY_PROJECT
NO_NEW_ROUNDS
RUNNING_ROUNDS_WAITED_TO_FINISH
STOP_REASON
```

如果批次在时间预算和轮次预算尚未耗尽前结束，主管摘要必须明确解释提前结束原因：

- 所有项目均达到硬终止状态。
- 用户明确要求暂停。
- 调度器发生误判并已记录修正。

不得把 `READY_FOR_USER_REVIEW`、`REFERENCE_ONLY`、`WINDOWS_HOST_VALIDATION_PENDING` 或 actual screenshot unavailable 单独写成最终停止理由。此类软状态必须结合 remaining gaps、next recommendation、预算和轮次判断是否继续。

当 `AUTO_CONTINUE_WITHIN_BUDGET=YES` 且项目仍有可执行下一步时，主管摘要应把项目标记为 `ROUND_COMPLETE_CONTINUE_ELIGIBLE`，而不是直接标记为终止态。

## 阻塞字段

阻塞项必须明确：

```text
PROJECT_NAME
BLOCKER_TYPE
BLOCKER_DETAIL
USER_DECISION_NEEDED
SAFE_TO_CONTINUE_OTHER_PROJECTS
```

常见 `BLOCKER_TYPE`：

- `MODEL_MISMATCH`
- `WORKDIR_MISMATCH`
- `SOURCE_READONLY_FAILED`
- `POLICY_BLOCKED`
- `API_402`
- `TOOLCHAIN_MISSING`
- `DEEPCODE_OUTPUT_MISSING`
- `QWENCODE_OUTPUT_MISSING`
- `QWENCODE_MODEL_MISMATCH`
- `PROMPT_DELIVERY_UNKNOWN`
- `STATE_UNKNOWN`
- `USER_REVIEW_REQUIRED`

软状态不得混入硬阻塞字段。`REFERENCE_ONLY`、`QWENCODE_COMPARE_COMPLETED=NO`、`WINDOWS_HOST_VALIDATION_PENDING`、缺 actual screenshot、还有 remaining UI differences，都应进入 `NEXT_ACTION` 或 `REMAINING_WORK`，除非同时存在真实硬阻塞。

## crash recovery 摘要格式

```text
Outposts crash recovery 摘要：

- 恢复窗口：
- 读取的调度记录：
- 未读取的内容：
- Git/root 检查：

  - <PROJECT_NAME>：<LAST_KNOWN_STATUS>；证据：<CHECKPOINT_OR_OUTPUT_FILE>；下一步：<NEXT_ACTION>

```

## 并行调度结束摘要格式

```text
Outposts 并行调度结束摘要：

- 项目：<PROJECT_NAME>
  业务轮次：已完成 <X> / 上限 <Y>
  视觉轮次：已完成 <VX> / 上限 <VY>
  运行时长：约 <M> 分钟 / 预算 <B> 分钟
  最终状态：<STATUS>
  DeepCode 输出：<LATEST_DEEPCODE_REPORT_PATH_OR_NONE>
  QwenCode 输出：<LATEST_QWENCODE_REPORT_PATH_OR_NONE>
  构建结果：<BUILD_RESULT>
  测试结果：<TEST_RESULT>
  本轮完成：<SHORT_SUMMARY>
  剩余问题：<REMAINING_WORK_OR_NONE>
  阻塞：<BLOCKER_OR_NONE>
  下一步建议：<NEXT_ACTION>

全局判断：
- 可人工 review：
- 需要继续下一批调度：
- 需要用户决策：
- 明确失败/阻塞：
- 建议下一轮优先级：
```

## 用户验收反馈转下一轮任务格式

```text
USER_FEEDBACK_INPUT
PROJECT_NAME=<PROJECT_NAME>
SOURCE=<user/manual review/screenshot/build log>
FEEDBACK_SUMMARY=<concise summary>
ACCEPTANCE_GAP=<what is not acceptable yet>
NEXT_WORKER=<DeepCode_ONE_SHOT | QwenCode_ONE_SHOT>
NEXT_ROUND_OBJECTIVE=<what worker must address>
MUST_VERIFY=<build/test/manual check expected>
SUPERVISOR_PROVIDED_INPUT_FILES=<paths>
DO_NOT_REPEAT=<previous failed approach or prompt>
```

用户验收反馈不得被降级为普通建议。它应进入下一轮正式任务的目标和验收条件。

## 禁止报告方式

不得：

- 粘贴 DeepCode / QwenCode 长报告全文。
- 用“worker 说完成了”代替主管判断。
- 省略未运行的构建或测试。
- 隐藏模型、路径、授权、预算异常。
- 把子项目源码内容写入主管摘要。
- 把敏感信息写入摘要、checkpoint 或 report。
